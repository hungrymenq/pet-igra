# Джефф — ресурсы отдельного нового питомца

Комплект подготовлен из версии, которую пользователь проверил в игре как замену пингвина Боки. В этом комплекте модель получила отдельные имена и пути. Перенос под новым путём проверен чтением форматов и разрешением внутренних ссылок; появление отдельного питомца после подключения таблиц должен проверить администратор.

**Это готовые ресурсы модели и инструкция подключения. Здесь нет изменённых `elements.data`, `path.data`, серверных таблиц или автоматически назначенных ID. Одной установки ресурсов недостаточно для появления нового питомца.**

## Основной путь для таблицы путей

```text
models\npcs\宠物\jeff_fw\jeff_fw.ecm
```

Точка входа — **ECM**, а не SKI. ECM содержит составные игровые действия и события навыков; он обращается к SMD, который связывает сетку, скелет и движения.

## Что находится в архиве

| Файл / папка | Назначение |
|---|---|
| `models.pck.files\npcs\宠物\jeff_fw\jeff_fw.ecm` | Входная модель и 75 составных действий |
| `jeff_fw.smd` | Ссылки на сетку, скелет и 17 движений |
| `jeff_fw.ski` | Сетка Джеффа, UV, материалы и веса |
| `jeff_fw.bon` | Скелет на 240 костей и точки HH |
| `textures\jeff_fw.dds` | Общая текстура 2048×2048 с логотипом на медальоне |
| `tcks_jeff_fw\*.stck` | 17 движений |
| `Общие эффекты и звуки.txt` | Внешние зависимости, используемые из существующего клиента |
| `Состав и проверка.json` | Все ресурсы, контрольные суммы и результаты проверки |
| `План подключения.json` | Памятка о новых записях; не формат автоматического импорта |

Всего **22 ресурса модели**, 17 999 треугольников. Геометрия, скелет, DDS и STCK совпадают по байтам с проверенной игровой версией. В ECM/SMD/SKI изменены только ссылки для отдельного размещения.

## 1. Добавить ресурсы клиенту

Добавить содержимое `models.pck.files` в **models.pck**, сохранив пути относительно этой папки:

```text
npcs\宠物\jeff_fw\jeff_fw.ecm
npcs\宠物\jeff_fw\jeff_fw.smd
npcs\宠物\jeff_fw\jeff_fw.ski
npcs\宠物\jeff_fw\jeff_fw.bon
npcs\宠物\jeff_fw\textures\jeff_fw.dds
npcs\宠物\jeff_fw\tcks_jeff_fw\…
```

`models.pck.files` — папка выгрузки, **не дополнительная папка внутри архива**. В логическом пути из таблиц используется префикс `models\`; внутри `models.pck` путь начинается с `npcs\`.

Нельзя устанавливать прежнюю замену из папки `宠物_企鹅` вместе с этим комплектом, если Боки должен остаться оригинальным. Если прежний тестовый патч уже установлен, вернуть оригинальные ресурсы Боки из его резервной копии, затем добавить этот комплект. Для проверки отдельного питомца желательно использовать чистый тестовый клиент.

## 2. Зарегистрировать новый путь

В редакторе данных добавить **новый свободный ID пути** с адресом:

```text
models\npcs\宠物\jeff_fw\jeff_fw.ecm
```

В имеющихся схемах проекта такие ссылки находятся в `path.data`; поля внешности питомца хранят ID пути, а не строку файла. Применить порядок синхронизации клиентских и серверных данных, принятый для конкретной сборки. ID и существующие пути Боки не менять.

## 3. Создать отдельную запись питомца

В имеющихся схемах проекта таблица называется **`PET_BEDGE_ESSENCE`** — именно `BEDGE`.

1. Создать новую запись с новым свободным ID и именем **«Джефф»**. Для начала удобно клонировать рабочую запись Боки в редакторе той же версии данных.
2. В нужных полях `file_to_shown_0` … `file_to_shown_9` указать **новый ID пути ECM**. Если все стадии должны выглядеть одинаково, для используемых стадий назначить этот путь. Назначение каждого слота сверить со схемой своего клиента.
3. Выставить параметры, навыки, требования и качество для нового питомца по решению администратора. Клонирование записи копирует и баланс донора; модель сама его не задаёт.
4. `default_pet_egg_id` связать с новым предметом призыва из следующего шага.

Не переносить числовые ID и смещения из другой версии `elements.data`. Поля и схема должны соответствовать версии рабочей сборки администратора.

## 4. Создать отдельный камень призыва

В имеющихся схемах проекта предмет призыва находится в **`PET_EGG_ESSENCE`**.

1. Создать новую запись с новым свободным ID, например с именем **«Камень призыва Джеффа»**.
2. В `id_pet_bedge` поставить **ID нового Джеффа**, созданного в `PET_BEDGE_ESSENCE`.
3. Настроить требования, уровень силы, привязку, торговлю и остальные свойства по правилам сервера.
4. Указать этот ID в `default_pet_egg_id` новой записи питомца.
5. Синхронизировать изменения в данных клиента и сервера. Для теста выдать новый предмет через штатные средства администратора; добавление в магазин, дроп или награды выполняется отдельно.

## Значки и портреты

Отдельные новые иконки и портреты в этот комплект не входят. Для первого теста можно сохранить ссылки донора; для окончательного выпуска администратор может заменить `file_icon`, `file_head_icon`, `file_self_head_icon` и другие нужные поля своими ресурсами. Это не влияет на готовую трёхмерную модель Джеффа.

## Движения и эффекты

- AFK / оба действия отдыха `休闲`, `休闲1`: **`104771_1047_SpitOut`**, скорость 75%.
- Общее движение `技能攻击2`, включая бафы хозяина: **`104721_WaterBomb`**, скорость 75%. Это движение разделяют и другие навыки, которые обращались к тому же действию ECM.
- Направление модели исправлено: поворот на 180° относительно первоначального экспорта. Эта версия уже проверена пользователем в игре.
- Глаза, подушечки лап и UV исправлены. На медальоне логотип игры.
- Все 12 постоянных декоративных эффектов донора убраны: `CoGfxNum: 0`.
- События применения навыков, их эффекты и звуки сохранены. Внешние GFX/ATT/SFX взяты из существующего клиента и перечислены в `Общие эффекты и звуки.txt`. Их наличие требуется проверить в клиенте администратора. При различии клиентских наборов их нужно перенести из совместимого донора либо адаптировать события ECM.
- Имена пингвина в путях общих эффектов или звуков **не означают зависимость от его SKI/BON**. Эти общие ресурсы переименовывать не требуется.
- Общие эффекты качества питомцев, включая орбиты, могут добавляться игровой логикой отдельно от модели.

## Проверка перед выпуском

1. Убедиться, что Боки остался прежним, а Джефф доступен через **новый** предмет и ID.
2. Призвать Джеффа; проверить текстуру, глаза, лапы и медальон.
3. Проверить стояние, оба отдыха, следование, бег, плавание, атаки, баф хозяина, получение урона и смерть.
4. Проверить нужные стадии качества / улучшения, повторный призыв и отображение у второго клиента.
5. Проверить иконки, портреты, характеристики, навыки и способ получения. Только после этого выпускать обновление для игроков.

**Итог:** Боки и Джефф используют разные пути ресурсов. Джефф станет самостоятельным питомцем после добавления новых связанных записей в данные игры.
